# Спецификация REST API SmartFrost App V2  за 31.05.2026

## Подтверждение по почте и вход в учетную запись пользователя

### GET /verification-code
Отправляет код подтверждения на указанную почту

Параметры в URL:
* email - **строка**; на эту почту придет шестизначный код

Тело ответа:
* message - **строка**:\
"ok", если код успешно отправлен\
"Error: [текст ошибки]", если что-то пошло не так

### POST /verification-code
Подтверждает почту по данному шестизначному коду.\
Возвращает *почтовый* JWT-токен для авторизации на *определенных* эндпойнтах\
Следует разделять *почтовые* и *пользовательские* токены:\
*Почтовый* токен создается в результате подтверждения электронной почты и применяется в операциях, требующих подтвержденную почту.\
*Пользовательский* токен создается в результате простого входа по паролю и применяется в большинстве операций.

Тело запроса:
* email - **строка**; электронная почта, которую нужно подтвердить
* code - **строка**; шестизначный код, который пришел на эту почту

Тело ответа:
* message - **строка**:\
"ok", если почта подтверждена и создан *почтовый* JWT-токен\
"invalid", если код некорректен
* token - **строка**; *почтовый* JWT-токен, завязанный на адресе электронной почты

### POST /login
Выполняет аутентификацию по почте и паролю

Тело запроса:
* email - **строка**
* password - **строка**; (незашифрованный; создание хэшей происходит на бэкенде)

Тело ответа:
* message - **строка**;\
"ok", если аутентификация прошла успешно\
"incorrect", если пользователя не существует, либо данные неверные
* token - **строка**; *пользовательский* JWT-токен

## Операции с данными учетной записи пользователя

### GET /users
Возваращает имя и действительную эл. почту пользователя

Параметры в URL:
* token - **строка**; *пользовательский* JWT-токен

Тело ответа:
* message - **строка**;\
"ok", если пользователь найден и авторизован\
"bad token", если токен не действителен\
"user not found", если пользователь не найден
* user - **объект (словарь)** со следующими полями: id (**int**), name (**строка**), email (**строка**)

### POST /users
Создает новую учетную запись о пользователе\
*Требуется подтверждение почты*

Тело запроса:
* name - **строка**; имя пользователя
* password - **строка**; пароль (незашифрованный; шифрование происходит на бэке)
* token - **строка**; *почтовый* JWT-токен

Тело ответа:
* message - **строка**:\
"ok", если пользователь успешно создан\
"bad token", если токен недействителен\
"email exists", если учетная запись с данной почтой уже существует\
"error", если внутри работы с БД возникла неопределенная ошибка (очень маловероятно)

### PUT /users/name
Меняет имя пользователя

Тело запроса:
* name - **строка**; новое имя пользователя
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если имя успешно изменено\
"bad token", если токен недействителен\
"error: [текст ошибки]", если возникла неопределенная ошибка

### PUT /users/password
Меняет пароль пользователя, который авторизован и имеет токен на руках

Тело запроса:
* password - **строка**; новый пароль (незашифрованный; шифрование происходит на бэке)
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если пароль успешно изменён\
"bad token", если токен недействителен\
"user not found", если пользователь не найден в БД\
"error: [текст ошибки]", если возникла неопределенная ошибка

### PUT /users/password
Меняет пароль пользователя\
*Требуется подтверждение почты*

Тело запроса:
* password - **строка**; новый пароль (незашифрованный; шифрование происходит на бэке)
* token - **строка**; *почтоый* токен

Тело ответа:
* message - **строка**:\
"ok", если пароль успешно изменён\
"bad token", если токен недействителен\
"no user with this email", если в БД нет пользователя с указанной почтой\
"error: [текст ошибки]", если возникла неопределенная ошибка

### PUT /users/email
Меняет электронную почту пользователя\
*Требуется подтверждение почты*

Тело запроса:
* user_token - **строка**; *пользовательский* токен (подр-ется, что пользователь авторизирован)
* email_token - **строка**; *почтоый* токен от новой почты

Тело ответа:
* message - **строка**:\
"ok", если пароль успешно изменён\
"bad user token", если *пользовательский* токен недействителен\
"bad email token", если *почтовый* токен недействителен\
"error: [текст ошибки]", если возникла неопределенная ошибка


## Операции с продуктами пользователей

### GET /items
Возвращает список продуктов пользователя

Параметры в URL:
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если список продуктов найден\
"bad token", если токен недействителен
* items - **массив** *объектов*, имеющих следующие поля:\
id (**int**),\
name (**строка**),\
category (**строка**),\
expiration (**строка** или **null**),\
quantity (**float**),\
unit (**строка**),\
deleted (**bool**)\
Массив может быть пустым, если у пользователя нет никаких продуктов

### POST /items
Добавляет продукты пользователя в его список в БД

Тело запроса:
* items - **массив** *объектов* с полями:\
name (**строка**),\
category (**строка**),\
expiration (**строка** или **null**) - строка должная быть в формате, удобоваримом для DateTime, иначе примется как null\
quantity (**float**),\
unit (**строка**)
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**;\
"ok", если операция прошла успешно\
"bad token", если токен не действителен

### PUT /items/delete
Удалить указанные продукты пользователя.\
(на самом деле продукты не удаляются из БД моментально, а помечаются на удаление - поле "deleted")

Тело запроса:
* item_ids - **массив** *int-ов* - идентификаторов продуктов, которые нужно удалить
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**;\
"n items deleted", если n продуктов было удалено (если n равно 0, возможно, что не удалось найти пользователя)\
"bad token", если токен недействителен

### PUT /items
Обновить данные указанных продуктов

Тело запроса:
* token - **строка**; *пользовательский* токен
* items_upd - **массив** *следующего вида*:
```
"items_upd": [
    // n - int; ID продукта
    // field1, field2 - поля, которые хотите обновить, а рядом  - новое значение поля
    // обновятся только те поля, которые указаны
    // поля "id", "user_id", "deleted" обновить нельзя
    [n, {"field1": ..., "field2": ..., ...}],
    [n, {"field3": ..., "field4": ..., ...}]
]
```

Тело ответа:
* message - **строка**:\
"n items updated"; обновлено n товаров\
"bad token", если токен недействителен

## Работа с QR-чеками пользователей

### POST /qr-text
Ищет купленные товары на стороннем API по заданному значению из QR-кода.\
Сохраняет данные QR-кода в БД в виде некой истории покупок пользователя.

Тело запроса:
* qrraw - **строка** *вида* "t=20260517T131059&s=554.01&fn=7380440902180698&i=57213&fp=2292136839&n=1"
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если данные по QR-коду успешно найдены\
[название ошибки], если не получилось достать данные с proverkachecka.com\
"bad token", если токен недействителен
* db_response - **строка**; результат попытки сохранить чек в истории покупок:\
"ok", если чек успешно сохранился в БД\
"exists", если чек в БД уже существует\
"undefined error", если возникла неопределенная ошибка в работе БД (очень маловероятно)
* items - **массив** *объектов* с полями "name" (**строка**), "quantity" (**float**), "unit" (**строка**), "price" (**float**)

### GET /purchases
Достает историю всех сохраненных в БД покупок пользователя

Параметры в URL:
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если данные успешно возвращены\
"bad token", если токен недействителен
* purchases - **массив** *объектов* (чеков) с полями "id" (**int**), "qrraw" (**строка**; та самая, которая передается в /qr-text), "fp" (**int**; ФПД чека)

## Рецепты

### GET /recipes/general
Достает заголовки всех рецептов из БД

Параметры в URL:
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если все норм\
"bad token", если токен недействителен
* recipes - **массив** *объектов* с полями "id" (**int**), "name" (**строка**), "description" (**строка**), "icon" (**строка**)

### GET /recipes/specific
Достает конкретный рецепт по айдишнику

Параметры в URL:
* token - **строка**; *пользовательский* токен
* recipe_id - **int**; id нужного рецепта

Тело ответа:
* message - **строка**:\
"ok", если все норм\
"recipe not found", если в БД нет рецепта с таким id\
"bad token", если токен недействителен
* recipe - **объект** с полями:\
id - **int**\
name - **строка**\
description - **строка**\
icon - **строка**\
cook_time_minutes - **int**\
servings - **int**\
ingredients_json - **строка JSON**\
instructions - **строка**\
is_ai_generated - **bool**\
ingredients - **массив** *объектов* с полями "name" (**строка**), "category" (**строка**), "quantity" (**строка**), "optional" (**bool**), если удалось прочесть JSON-список ингредиентов; иначе **null**

### GET /recipes
Достает все рецепты пользователя с их полным описанием

Параметры в URL:
* token - **строка**; *пользовательский* токен

Тело ответа:
* message - **строка**:\
"ok", если все норм\
"bad token", если токен недействителен
* recipes - **массив** *объектов*, имеющих поля:\
id - **int**\
name - **строка**\
description - **строка**\
icon - **строка**\
cook_time_minutes - **int**\
servings - **int**\
instructions - **строка**\
is_ai_generated - **bool**\
match_percent - **int**; насколько рецепт совпадает с текущим наличием продуктов у пользователя\
missing_ingredients - **массив** *строк* - названий отсутствующих ингредиентов\
ingredients - **массив** *объектов* с полями "name" (**строка**), "category" (**строка**), "quantity" (**строка**), "optional" (**bool**), если удалось прочесть JSON-список ингредиентов; иначе **null**

### POST /recipes
Добавить новый рецепт в БД

Тело запроса:
* token - **строка**; токен разработчика (имеющий поле "is_dev" равное True)
* name - **строка**; название блюда
* description - **строка**; описание
* icon - **строка**; эмодзи-иконка блюда
* cook_time_minutes - **int**; время на готовку в минутах
* servings - **int**
* ingredients_json - **строка**; список ингредиентов в синтаксисе JSON: **массив** *объектов*;\
Каждый ингредиент должен иметь следующие поля:\
name - **строка**; название продукта-ингредиента\
category - **строка**; категория продукта\
quantity - **строка**; кол-во + единица измерения (e.g. "100 мл")\
optional - **bool**; опциональность ингредиента
* instructions - **строка**; текстом: как готовить

Тело ответа:
* message - **строка**:\
"ok", если рецепт успешно добавлен в базу\
"error: [текст ошибки]", если в процессе сохранения в БД возникла ошибка\
"bad token", если токен недействителен

## Прочие эндпойнты

### POST /notifications/tokens
Подключить push, email или web уведомления пользователю

Тело запроса:
* token - **строка**; *пользовательский* токен
* web_token - **строка** или **null**; токен для привязки web-уведомлений
* tel_token - **строка** или **null**; токен для привязки push-уведомлений
* email_notification - **bool**; разрешение на рассылку email-уведомлений

Тело ответа:
* message - **строка**:\
"ok", если пользователь успешно подписан на данные виды уведомлений\
"error: [текст ошибки]", если возникла какая-то ошибка в работе БД\
"bad token", если токен недействителен
